A whole form, one safeParse call

Fill in the form. Errors come back already grouped by field, and transforms such as trimming and lowercasing the email are applied to the data. Nothing is sent anywhere.

const signup = {
  email: validators.email,
  phone: (v) => validators.phone(v, 'international'),
  postcode: (v) => validators.zipCode(v, 'uk'),
  password: validators.password
};

const result = safeParse(signup, form);

Works with your form library

snap-validate implements Standard Schema, so React Hook Form, TanStack Form, tRPC, Hono and other compatible tools accept it without an adapter. 

import { useForm } from 'react-hook-form';
import { standardSchemaResolver } from '@hookform/resolvers/standard-schema';
import { validators, toStandardSchema } from 'snap-validate';

const signup = toStandardSchema({
  email: validators.email,
  phone: (value) => validators.phone(value),
  password: validators.password
});

const form = useForm({ resolver: standardSchemaResolver(signup) });
// errors.email.message -> 'Invalid email format'

Why snap-validate

No regexes to write
Presets cover email, US and international phone numbers, card numbers with a Luhn check, US, Canadian and UK postcodes, and password rules you can configure.
Plain JavaScript
No schema language and no TypeScript compiler needed. Type definitions are included if you use TypeScript.
Small on purpose
Zero dependencies and under 5 KB for the whole library, with the budget checked on every change. Works with require and import.
Safe with untrusted input
Input-length limits and a check that rejects regex patterns known to hang on crafted input.

When to pick something else: if you want TypeScript types inferred from your schemas, or deeply nested data schemas for an API, Zod or Valibot are a better fit. snap-validate is for checking what people type into forms with as little setup as possible.
